# 踩坑清单：现象 → 根因 → 规则

每一条都来自真实发生过的失败（或一次失败之后才建立的检查）。按主题分组，写法统一为：**发生了什么 → 为什么 → 现在的规则**。

---

## A. 判定与验收纪律

### A-01 自报的指标要独立复测，不能采信

**发生了什么**：某轮修复后 builder 自报「IoU = 1.000000」，captain 用独立方法复测，该值不成立。
**根因**：指标由实现者计算，计算口径与实现共享同一处错误（掩膜来源、滤波、坐标口径）。
**规则**：任何用于放行的关键指标，必须由**不读实现者中间产物**的独立脚本复算。自报值只作为线索。

### A-02 局部关系验证不能替代整体形状验证

**发生了什么**：射线命中、包围盒、深度顺序全部 `PASS`，但第一眼看模型仍然「不像」。
**根因**：这类证据只证明**局部关系**（某个点在某面之前），不证明轮廓、比例、面积或视觉识别。
**规则**：宣告视觉 `PASS` 需要两路同时通过——**局部关系验证 + 整体原画对照**。只有一路时判 `UNKNOWN`。

### A-03 禁止用代理量宣告形状正确

**发生了什么**：用 `bbox`、可见面积、最大行宽、探针命中数量来论证「形状已经对了」。
**根因**：这些量对轮廓错误不敏感——把轮廓整体平移或轻微变形，它们几乎不变。
**规则**：`IoU` 一类相似度指标**只记录、不参与验收**；禁止用 `bbox` / 面积 / 行宽 / 探针数量宣告形状正确。验收以「第一眼能否读成…… 」这类视觉判读为准，最终裁定权在用户。

### A-04 不要写绝对排除式断言

**发生了什么**：写了「完全排除几何原因」，但实际证据只能支持「几何不是主因」。
**根因**：把「没有证据支持 X 是主因」表述成「X 已被排除」，是证据强度的越权。
**规则**：改用主因表述，例如 `FACETING_MAJOR_CAUSE = NORMALS / SHADING`；残余现象如实记为低等级观察项，不改写成「不存在」。

### A-05 `FAIL` 不得被弱化

**发生了什么**：视觉检查已证明主要结果错误，报告里写成「基本正确，仍需确认」。
**根因**：把验收条件的解释权留给了实现者。
**规则**：存在直接证据违反验收条件即为 `FAIL`；依赖该错误结果的后续结论全部失效，停止沿它继续加工。改写要求、反转前后关系、放宽验收定义、换指标后宣布通过——四项均禁止。

### A-06 存在被推翻的判断时，如实登记

**发生了什么**：captain 的三处判断被 verifier 推翻；另一轮 captain 发现自己此前的登记有误。
**根因**：维持面子比维持事实便宜。
**规则**：被推翻的判断写进台账（谁推翻、依据是什么、原判断错在哪），并在交付说明里保留。被证伪的旧结论要主动替换，留着会持续污染后续判断。

### A-07 边界按图像实际边缘定，不按像素网格中心定

**发生了什么**：因为数据存在像素 `mask` 里，就默认轮廓必须穿过某一类像素的中心。
**根因**：把存储格式当成了几何约束。
**规则**：几何边界可以位于两个像素中心之间；轮廓点由建模者目视判断，禁止用自动分割/逐像素追踪代替判断。

### A-08 `UNKNOWN` 是合法结论

**发生了什么**：为了「分类完整」或「收口」，把看不清、证据不足的结构强行判定。
**根因**：把「本轮必须有结论」当成了验收要求。
**规则**：证据不足就记 `UNKNOWN`，并写清缺什么证据才能判定。`UNKNOWN` 清单只增不减地被带进交付说明。

## B. 几何与像素

### B-01 Python 负数整除：`-win // 2` 不是 `-1`

**发生了什么**：窗口平滑里用 `-win // 2` 取边界，实际得到 `(-3)//2 = -2`（不是 `-1`），平滑时累加了 4 个邻点却除以 3 → **所有坐标被放大 4/3**，平滑两次放大到 1.7778×。方块单元测试完全没暴露它，因为那条用例 `smooth=0`，根本没走平滑分支。
**根因**：负数整除语义 + 测试未覆盖参数组合分支。
**规则**：涉及索引与窗口的边界运算先算一遍负数用例；**单元测试必须覆盖每个分支的参数组合**，不能只测「能跑通」的那一组。

### B-02 边界跟踪的判据要用手推的极小样例验证

**发生了什么**：竖边判据写成 `ev = A != C`（左上格 vs 左下格），正确应为 `ev = C != D`（左格 vs 右格）→ 每条上边界长出一根向内的假竖边，跟踪器走成「梳齿」，得到的全是面积 0 的退化环。
**根因**：判据写错但整链仍「跑完」，错误只体现在结果形态上。
**规则**：轮廓/跟踪类算法先用 3×3 手推样例验判据，再上真图；跑完不等于跑对。

### B-03 剪影处理最危险的两种操作：膨胀 1 px、填满所有内部空洞

**发生了什么**：剪影 `mask` 做膨胀 1 px + 填满全部内部空洞后，原图里 3650 px 的空隙（腋下、剑与身体之间）被糊死，角色凭空变胖。用户指出「你现在用的图其实并不准确」——事后证明该判断正确。
**根因**：把「让掩膜更干净」当成了纯收益，没有量化它对面积的改变。
**规则**：任何形态学操作后必须报**面积变化量**与**逐行边界变化**；填洞只能填「已知应当实体」的区域，不能无条件填全部。

### B-04 修 bug 的补丁本身要再验一次语义方向

**发生了什么**：修 B-03 时，`comps(mask, 40)` 返回的是「面积 ≥40 的洞」，却被当作「要填的洞」→ 变成「只填大洞、留下所有碎洞」，与意图相反。
**根因**：函数返回值的语义方向没核对（返回的是候选还是待处理项）。
**规则**：补丁落地后，用**一个能区分方向的样例**验证（此处：小洞应被填、大洞应保留），不能只看「不再报错」。

### B-05 正面正光会掩盖浮雕缺陷

**发生了什么**：正面打光下渲染「看起来挺平」，实际表面是碎石状起伏。
**根因**：正光下法线偏差不产生明暗差。
**规则**：验收浮雕必须用**掠射光**（近平行于浮雕面）+ 3/4 视角；正光只用于确认轮廓与遮挡。

### B-06 手工轮廓吸附：控制点必须稀疏，且先吸附锚点

**发生了什么**：live-wire 控制点放太密时完全不吸附边，路径直穿平坦区。
**根因**：A\* 的绕路代价只有在「沿边省下的代价 > 绕路代价」时才划算；控制点密到贴着边，绕路就没有收益。控制点落在平坦区内部时，A\* 选择直行。
**规则**：控制点只在**角点**放（±5~7 px 精度即可），且每一步先 `snap_anchor` 再求路径。

### B-07 视觉上变差的尝试必须回退

**发生了什么**：给部件加 Chaikin 圆角，部件变成圆滑卵石，结构全丢。
**根因**：把「更平滑」当成了「更好」。
**规则**：每轮改动后与原画对照，**变差就回退**，不因为已经投入轮次而保留。回退也是要记录的结论。

### B-08 碎片化 ≠ 边界不准

**发生了什么**：分水岭分割出的 26 块散在 5 个深度层上，看起来「边界一塌糊涂」。
**根因**：难看来自**碎片化**，而分水岭区域的边界本身是准确的原画边缘。
**规则**：先按语义合并碎片（帽子 = 帽冠 + 三块帽檐；大衣 = 胸 + 躯干 + 两前襟 + 腰带），往往直接得到连贯精确的大形。合并失效的地方才是真的边界问题（例：帽子内部边界落在帽带而非帽檐外缘）。

### B-09 对照用的原画掩膜要先去掉暗描边造成的孔洞

**发生了什么**：原画剪影逐行比对时出现大量「孔洞」误差。
**根因**：线稿的深色描边在阈值化后成为背景。
**规则**：原画剪影按**每行首末非背景像素做行填充**，再做逐行左右边界比较。

### B-10 判定性证据要用无滤波的几何通道

**发生了什么**：不透明渲染在某条带上最大差 43 px，看上去像几何错误。
**根因**：1.5 px 重建滤波导致边缘像素部分覆盖（与 alpha 抖动同类）。
**规则**：涉及边界判定的证据改用 `ray_cast` **命中图**（纯几何、无 AA、无滤波）；渲染图用于观感判读。

### B-11 亚像素级差异记 `UNKNOWN`，不判外扩

**发生了什么**：少数行差 5–32 px，全部落在 ≤6 px 宽的细碎区间上。
**根因**：这类差异是亚像素归属问题，不是形状错误。
**规则**：把「细碎区间 + 小差值」这一类单独定义（如「亚像素归属」），记 `UNKNOWN`；不为了凑一个干净的 `0` 而改口径。

## C. 单位与坐标

### C-01 两套口径混用 = 此前所有对照结论作废

**发生了什么**：px→mm 用了项目口径常数 `K = 200/296 = 0.675676`，而正交对照用的是渲染口径 `ORTHO = PW × 1.1261`；两者混用后「原画对照」整体缩放约 **0.6 倍**，那一整轮对照结论作废重做。
**根因**：项目里同时存在两套都能把「像素」和「毫米」联系起来的口径，而文档没写明哪套用于哪里。
**规则**：单位口径表里必须**逐项写明用途**（几何计算 / 相机正交对照 / 导出缩放），并声明唯一 source of truth。

### C-02 任何 Blender 修改之前，先做坐标往返预检

**发生了什么**：早期直接开始建模，等到对照阶段才发现投影口径不对。
**根因**：投影链路（源图像素 → 世界坐标 → 相机像素 → 源图像素）没有被验证过。
**规则**：`SRC → WORLD → CAMERA_PIXEL → SRC` 往返至少 **5 个已知点**，每点误差 ≤ **0.5 源像素**；失败立即停止，不允许继续 overlay / IoU / probe / 建模。脚本见 `../tools/unit_roundtrip_check.py`。

### C-03 改单位后的下游回归是必做项

**发生了什么**：把场景单位改成 `1 unit = 1 mm` 后，此前用「米」写的判定阈值、深度表、相机距离全部失效。
**根因**：单位是全局状态，改动会静默改变所有数值的含义。
**规则**：单位改动记入 `UNIT_CONVENTION.md` 的变更记录，并列出**下游必须重跑的检查清单**（深度表、阈值、导出缩放、相机参数）。

### C-04 导出前确认三个硬性状态

`scene.unit_settings` 与目标口径一致；对象 `scale = (1,1,1)`（无未应用的缩放）；总高/总宽已归一化到目标尺寸（例：含底座总高 120 mm）。三者都要有实测输出，不能凭记忆。

### C-05 区间与 bbox 用闭开规则写明

**发生了什么**：同一个「层深度」在脚本 A 里按 `[lo, hi)`、在脚本 B 里按 `[lo, hi]`，边界行归属不一致，差分图出现整行假差异。
**根因**：区间约定没写明。
**规则**：所有区间在文档里写明闭开规则（含 bbox 的行/列归属），脚本里用统一前缀常量表达。

### C-06 单位改动要落到「用户可复核的报告」

交付说明里给**两套口径的数值**：场景单位下的数值 + 实际毫米尺寸，并写清换算链。用户需要拿它核对切片软件里的尺寸，而不是猜。

## D. Blender / bpy 工具链

### D-01 `工具执行成功` 只是传输成功

**发生了什么**：MCP 回 `Code executed successfully`，几何其实是错的（甚至整片全黑）。
**根因**：返回值只表示 Python 没抛异常。
**规则**：MCP 的返回值**永远不构成验收证据**；必须渲染截图 + 对照原画。此条是全部规则里最容易忘记的一条。

### D-02 版本相关的枚举与属性会变

**发生了什么**：`BLENDER_EEVEE_NEXT` 不存在（5.2 的枚举是 `BLENDER_EEVEE`）；`Principled BSDF` 的 `Specular` / `Emission` 参数、`mesh.use_auto_smooth` 的用法在版本间已变。
**根因**：照搬旧版本记忆。
**规则**：写 `bpy` 前先用 API 查询工具（或 `bpy.types` 内省）确认名称与枚举；不凭记忆写。

### D-03 埋在模型内部的灯会让渲染全黑，且点光源不受旋转影响

**发生了什么**：场景里原有的 `Light` 是点光源（能量 3，位置在模型内部），渲染全黑；改它的方向后两次渲染**字节完全相同**——因为点光源没有方向。
**根因**：只改了「看起来应该有用」的参数，没验证参数是否作用。
**规则**：渲染异常先查灯的类型/位置/能量，再看材质；两次输出字节相同 = 参数根本没生效，别再调它。

### D-04 Solid 模式取的是 `material.diffuse_color`，不是 Principled 的 Base Color

**发生了什么**：视口 Solid 模式设了节点基色，渲出来整片全灰。
**根因**：`color_type='MATERIAL'` 读 `material.diffuse_color`。
**规则**：语义分色诊断要同时设节点基色与 `diffuse_color`；两者不一致时以视口显示为准来判读。

### D-05 离屏渲染不响应部分 shading 改动

**发生了什么**：`light='FLAT'`、`color_type='SINGLE'`、`background_type` 等设置后，得到的「整片白剪影」其实是设置没生效。
**根因**：`bpy.ops.render.opengl` 与视图 shading 状态的耦合不完整。
**规则**：要可信剪影，用**正常渲染一次 + 隐藏全部网格再渲染一次做差分**（与光照无关），不要依赖 shading 开关。

### D-06 用 `bpy.data.images` 写 PNG 的两个坑

`images.new(...)` 建出的是 RGBA，喂 RGB 数组会报 `expected sequence size`；`pixels` 期望 0..1 浮点，忘了除以 255 会把背景灰截断成纯白。写图前先确认**通道数**与**数值范围**。

### D-07 中文界面下按类型取节点，不按名字

界面语言为中文时，材质节点显示名被本地化，`nodes.get("Principled BSDF")` 返回 `None` 并抛 `AttributeError`。一律按 `node.type` 取（`BSDF_PRINCIPLED` / `OUTPUT_MATERIAL` / `TEX_IMAGE`）。

### D-08 连通性判定不要只做顶点采样

**发生了什么**：两件物体实际相交，但顶点采样（步长 `len/24`）漏掉了背板底边那 4 个顶点，把连通分量从 1 判成 2。
**根因**：采样是**假象**来源——采样漏点会制造「不连通」，采样过密会制造「相交」。
**规则**：先做**三角形级相交**（`BVHTree.overlap`），再用顶点包含做兜底，两层结果都落盘。

### D-09 死循环会挂死 MCP 主线程

**发生了什么**：`while len(lad) < 60` 而候选窗口只有有限个值 → 循环永不退出，**把 MCP 端的 Blender 主线程挂死**（请求超时、后续调用全部无响应）；Blender 进程被重启，内存中的场景丢失（磁盘产物完整）。
**根因**：循环终止条件依赖「候选足够多」，而候选是有限集。
**规则**：任何「凑够 N 个」的循环都要有**无新增即退出**的兜底；构建脚本必须可**确定性重建**内存场景（把状态留在脚本与磁盘产物里，不留在内存）。

### D-10 体素并集与布尔并集：按需选，并复查细节损失

水密合并用体素并集稳定但会抹平浅浮雕；布尔并集保细节但对退化面敏感。**无论选哪种，都要做合并前后的定点探针 + 逐像素前表面深度差**，把细节损失写成数字进交付说明。

## E. 流程与产物管理

### E-01 阶段脚本必须声明 `STAGE_NAME`，且默认不覆盖

**发生了什么**：脚本里写死了旧路径，把**上一阶段**的 `.blend` 覆盖掉了，前一轮的事实基础消失。
**根因**：保存路径由脚本硬编码，而不是由阶段名推导。
**规则**：脚本显式声明 `STAGE_NAME`，保存路径由它生成；目标 `<STAGE_NAME>.blend` **已存在则停止并报告**。同轮内确实要重跑时，先把旧产物改名保留（如 `*_dev1.blend`），不得直接覆盖。守卫脚本见 `../tools/stage_guard.py`。

### E-02 幂等清理不全 → 假 `FAIL`

**发生了什么**：阶段 2 重建时场景里残留底座对象，把「最大前凸 / 总厚」报成 31.9 / 63.8 mm 的假 `FAIL`。
**根因**：清理逻辑只覆盖本阶段自己的对象，没清理上游残留。
**规则**：每个阶段脚本开头按**对象名前缀**做一次全量幂等清理；报告中打印「本轮实际存在的对象集」，让残留无处可藏。

### E-03 整链重建会悄悄覆盖掉已经修好的局部

**发生了什么**：某轮把 n 边形拓扑修好后，下一轮整链重建又把它变回 840 面（原为 300 面）。
**根因**：修复存在于产物里，却不在生成路径里。
**规则**：任何修复都要落到**生成脚本**中；并在构建期加断言，让「拓扑回退」在构建时直接失败，而不是悄悄写进产物。

### E-04 自检脚本与实现共享假设 = 假通过

**发生了什么**：builder 的 `check_stageN.py` 与其构建脚本共用同一套层深常量，常量本身错了，两边一起错，校验全绿。
**根因**：校验读的是实现的中间量，不是独立的产物事实。
**规则**：校验脚本尽量只读**磁盘上的产物**（`.blend` / `.stl` / 导出文件），需要的基准值从契约文件重新解析，不从构建脚本 import。

### E-05 修 A 时新引入的偏离要显式登记，哪怕只有 7 px

**发生了什么**：修复后还剩 7 px 差异，其中 6 px 是基线越界覆盖、1 px 是亚像素边界点。为了凑「0」而恢复基线的越界覆盖，会违反「不得超出原画轮廓」的约束。
**根因**：「差异 = 0」被当成了目标，而真正的目标是两条约束同时成立。
**规则**：冲突时保留约束、登记差异（写成 `OBS-xx` 条目），并写明为什么不修。

## F. 环境与工具链（本机踩过的）

### F-01 PowerShell 5.1 读 UTF-8 无 BOM 文件会乱码

**发生了什么**：`Get-Content` 不带 `-Encoding` 时按系统 ANSI 代码页（本机 GB2312）解码，UTF-8 无 BOM 文件变乱码；GBK 尾字节范围 `0x40–0x7E` 含 ASCII 字母数字，**中文后面的 ASCII 字符会被吞掉**。实测两个后果：含中文的 UTF-8 无 BOM `.ps1` 用 `powershell.exe -File` 执行**直接解析失败**（吞掉了引号）；同一台机器上，仓库扫描脚本对「ASCII 前缀 + `ghp_token`」检出 `FAIL`，对「中文前缀 + 同一 token」检不出（`PASS`）。
**规则**：给 Windows PowerShell 5.1 写的 `.ps1` 一律**纯 ASCII 源码**，或存成带 BOM 的 UTF-8；读文件内容做扫描时显式 `[IO.File]::ReadAllText(path, UTF8)`，不要 `Get-Content -Raw`。pwsh 7 不受影响。

### F-02 受限沙箱下的几种「拒绝访问」不是你的命令写错了

- `npm.cmd` / `corepack.cmd` 一类 shim 可能无法执行 → 用 `npm i -g pnpm` 之后直接调用安装后的可执行文件；
- `Invoke-WebRequest` / `Invoke-RestMethod` / `curl.exe` 因受限令牌触发 Schannel `SEC_E_NO_CREDENTIALS`，**设代理也无效** → 改用 Node 或 Python 发起网络请求；
- `git.exe` 在本次实测中**可用**（`git --version`、`git init -b main` 均成功）；若某个环境报 `Program 'git.exe' failed to run: 拒绝访问`，先换一种调用方式重试，仍不行再改走 Node + GitHub API（先取 tree 清单，再逐个取 raw 文件），并把 `commit` / `push` 放到**用户自己的终端**执行；
- **命令放进管道后可能被拒**：`python script.py | Select-Object ...` 报 `Program 'python.exe' failed to run: 拒绝访问`，同一条命令直接运行则正常 → 不要在受限沙箱里用管道捕获子进程输出，改为让脚本自己写报告文件，或直接看标准输出。
**规则**：遇到这类错误先判断是**策略拒绝**还是命令错误；策略拒绝就换工具链，不要在同一个命令上反复试。

### F-03 pwsh 里的重定向与外部工具

`2>$null` 会报 `StandardErrorEncoding is only supported when standard error is redirected`；`> $null` 同样报 `StandardOutputEncoding is only supported when standard output is redirected`（两者都是**关闭流**而不是重定向，平台直接拒绝）→ 需要丢弃输出时改写文件或直接省略；某些压缩工具（如 `zstd.exe`）需要**绝对路径**调用，否则报「拒绝访问」。

### F-04 环境能力要先探测再依赖

本机 Python 环境**没有 PIL** → 图像读写改走 Blender 自带的 `numpy` + `bpy.data.images`（或用标准库自己解 PNG）。依赖某项能力前先跑一次最小探测脚本，把结论写进项目文档。

### F-05 宿主侧抓取与本地网络栈是两条路

内置的网页抓取工具由宿主发起、不受本机代理影响，可能拿不到某些站点（如 GitHub）；本机 Node/Python 走系统代理则常常可以。**两条路都试**，并把可用的那条写进项目文档，避免下次重复摸索。

### F-06 受限沙箱下系统临时目录可能不可写

**发生了什么**：自测脚本用 `tempfile.TemporaryDirectory()` 建临时目录，`write_text()` 报 `PermissionError: [Errno 13]`（路径在 `AppData\Local\Temp\...`）；随后的 `shutil.rmtree` 清理再次被拒（`WinError 5`），把原本的断言失败盖成了一串清理异常。
**根因**：沙箱的可写范围是会话工作区，系统临时目录不在其中。
**规则**：脚本的临时产物放在**工作区内**的子目录（测试结束即删，并写进 `.gitignore`），不要依赖系统临时目录；同理，包管理器与构建工具的缓存目录也指到工作区内。这样测试在任何沙箱策略下都可运行。
