## 3. px → <单位> 换算（唯一 source of truth）

### 3.1 基准与常量（冻结）

| 常量 | 值 | 来源 |
|---|---|---|
| 目标长度 | <例：总高 120.0 mm> | 用户原话 / DECISIONS.md |
| 参考图像素数 | <例：296 px> | 实测（写出测法） |
| **K** | <例：120/296 = 0.4054054 mm/px> | 上两行相除 |
| 原点 | <例：src(141.5, 402.0) → world(0, 0)> | 实测（写出测法） |
| 深度符号 | <例：d 越大越靠前 → Y = −d> | 坐标轴约定 |
| 画面中心 | <例：world(2.4324, 81.6892)> | 由原点与图幅推导 |

> **K 不要跨项目复用**；也不要手抄小数展开——文档里的数值必须由脚本输出回写。

### 3.2 换算函数（可直接执行）

```python
K = 0.4054054
OX, OZ = 141.5, 402.0

def src_to_world(px, py):
    return ((px - OX) * K, (OZ - py) * K)   # (X, Z)

def world_to_src(x, z):
    return (x / K + OX, OZ - z / K)
```

### 3.3 两套口径的分工（**混用会静默出错**）

| 口径 | 用于 | 数值示例 |
|---|---|---|
| 几何口径 K | 像素 → 世界坐标（建模） | <值> mm/px |
| 相机正交口径 | 世界坐标 → 渲染图（对照） | `ortho_scale / max(W, H)` = <值> mm/px |

> Blender 的 `ortho_scale` 作用于渲染的**较长边**。两套口径的比值不必然为 1；若渲染与源图同帧，
> 则应接近 1。**明显偏离时先确认这是刻意的帧比例，还是把一套口径当成了另一套**（真实事故：
> 混用导致对照整体缩放约 0.6 倍，一整轮结论作废）。

### 3.4 往返预检（准入闸门）

- 链路：`SRC → WORLD → CAMERA_PIXEL → SRC`
- 至少 **5 个独立观测锚点**（同一特征在源图与渲染图上的像素坐标），覆盖四角与中心；
- 每点误差 ≤ **0.5 源像素**；
- 工具：`python tools/unit_roundtrip_check.py --spec roundtrip.spec.json`
- 报告：<报告文件路径>
- **失败即停止**：不允许继续 overlay / IoU / probe / 建模。
- 注意：只有**独立观测锚点**才能证明口径正确；纯数值往返自检不算证据（结论记 UNKNOWN）。
